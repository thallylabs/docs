---
title: Migrating to Thally
description: Move your existing documentation from Mintlify, Docusaurus, GitBook, or any Markdown-based platform to Thally in one command.
---

The `create-thally-docs migrate` command imports either a public documentation site or a GitHub docs repository and converts it into a running Thally project — no manual copying or navigation rebuilding.

```bash
npx create-thally-docs@latest migrate https://github.com/your-org/your-docs my-docs
```

<Note type="info" title="Repository migration is recommended">
A GitHub repository preserves authored navigation, assets, OpenAPI files, redirects, and MDX structure that may not be recoverable from a rendered website. Use a live docs URL only when the source repository is unavailable.
</Note>

---

## How it works

<Steps>

<Step title="Choose the source platform">

In an interactive migration, Thally asks whether the source is hosted by Mintlify, Docusaurus, or another platform. This selects the platform-specific importer before discovery starts.

If you choose **Other / detect automatically** with a live URL, the CLI offers the source GitHub repository first. Continuing with the website requires confirmation that the result may need manual alignment and recommends the [Thally MCP](/guides/mcp-server) for refinement.

For scripts and CI, pass `--platform mintlify`, `--platform docusaurus`, or `--platform auto`. Explicit `--platform auto` and `--yes` runs remain non-interactive, print the live-site limitation, and treat it as accepted.

</Step>

<Step title="Discover pages and navigation">

For a GitHub URL, Thally performs a shallow clone and reads the authored content and platform configuration without executing it. This is the recommended auto-detection path. For a live docs URL, Thally reconstructs the site from its sitemap, rendered sidebars, redirects, and page content within the submitted docs path.

Repository imports recognize these configuration files:

| File | Platform detected |
|------|-------------------|
| `docs.json` / `mint.json` | Mintlify |
| `docusaurus.config.js` + `sidebars.js` | Docusaurus |
| `book.yaml` | GitBook |
| `_meta.json` | Nextra |
| `vitepress.config.*` | VitePress |
| `.starlight/` | Starlight |
| *(none of the above)* | Directory structure used |

The docs directory is also auto-detected: `docs/`, `documentation/`, `content/`, `src/content/`, `pages/`, or the repo root. Docusaurus projects nested in monorepos and additional `plugin-content-docs` instances are discovered automatically.

</Step>

<Step title="Import all documentation files">

Repository migrations read every `.md` and `.mdx` file directly. Live-site migrations convert rendered documentation into portable MDX. Frontmatter, headings, links, code blocks, tables, tabs, and callouts are preserved where the source exposes them.

Non-Markdown files (e.g. `.rst`) are converted to MDX using Claude if you provide an Anthropic API key.

</Step>

<Step title="Wire up the API reference">

If an OpenAPI spec (`openapi.json`, `openapi.yaml`, `swagger.json`, etc.) is found anywhere in the repo, it is copied to `public/` and the API Reference tab in `docs.json` is set up automatically.

</Step>

<Step title="Write the Thally project">

All converted pages are written to `src/content/`. The `docs.json` navigation is built from the detected platform config or inferred from the directory structure.

</Step>

</Steps>

## Supported platforms

### Select a platform

Run without `--yes` to choose interactively:

```bash
npx create-thally-docs@latest migrate https://relay.dev/ relay-docs --max-pages 1000
```

For a non-interactive migration, select the platform explicitly:

```bash
npx create-thally-docs@latest migrate https://relay.dev/ relay-docs \
  --platform docusaurus \
  --max-pages 1000 \
  --yes
```

<Warning>
For auto-detection, prefer the source repository URL. A live URL can omit files and structure that are not present in the rendered site. Interactive runs require you to accept this limitation; `--platform auto` and `--yes` acknowledge it non-interactively.
</Warning>

### Mintlify

```bash
npx create-thally-docs@latest migrate https://docs.example.com my-docs --platform mintlify
```

Live sites and repositories are supported. Navigation is read from the rendered site, `docs.json` (Mintlify v3), or `mint.json`. OpenAPI specs in the `api-reference/` directory are detected and wired up automatically.

### Docusaurus

```bash
npx create-thally-docs@latest migrate https://relay.dev/ relay-docs --platform docusaurus
```

For live sites, Thally reconstructs the current-version sidebar hierarchy, follows canonical redirects, preserves case-sensitive routes, and excludes legacy/next version trees. Docusaurus admonitions, tabs, tables, and syntax-highlighted code blocks are converted to compilable Thally MDX.

For repositories, sidebar structure is parsed statically from `sidebars.js` or TypeScript equivalents. Nested monorepo projects, autogenerated categories, static assets, `@site` snippets, and additional docs plugins are supported. Source configuration is never executed.

The Docusaurus importer is verified against the complete current documentation sets for [Relay](https://relay.dev/), [Algolia DocSearch](https://docsearch.algolia.com/docs/what-is-docsearch), and [Hasura DDN](https://hasura.io/docs/3.0/index/).

### GitBook

```bash
npx create-thally-docs migrate https://github.com/your-org/gitbook-docs my-docs
```

`SUMMARY.md` is used to infer navigation order. `{% hint %}` blocks are converted to the appropriate Thally callout component.

### Plain Markdown

Any repository with Markdown files works — navigation is built from the directory structure.

```bash
npx create-thally-docs migrate https://github.com/your-org/docs my-docs
```

## Migrating into an existing project

Use `--into` to add content from another repo into an existing Thally project without overwriting it. New tabs and groups are merged; existing content is not touched.

```bash
npx create-thally-docs migrate https://github.com/your-org/api-docs --into ./my-docs
```

---

## Options

| Flag | Description |
|------|-------------|
| `--into <dir>` | Merge into an existing project |
| `--branch <name>` | Override the auto-detected git branch |
| `--docs-dir <path>` | Override the auto-detected docs subdirectory |
| `--platform <name>` | Source adapter: `mintlify`, `docusaurus`, or `auto` |
| `--max-pages <count>` | Maximum live-site pages to import, from `1` to `1000` |
| `--api-key <key>` | Anthropic API key (or set `ANTHROPIC_API_KEY`) for non-Markdown conversion |
| `--yes`, `-y` | Accept defaults and skip all interactive prompts, including platform selection |

## Via the MCP server

If you're using Claude Code or Claude Desktop, you can trigger a migration through chat:

```
Migrate the Mintlify starter repo into a new Thally project at ~/dev/my-docs
```

`migrate_docs` always scaffolds a fresh canonical Thally template before importing the source. Its target must be new or empty, so the result includes Thally's supported runtime, layout, navigation, and configuration.

Use `import_docs` only when you explicitly want to import content into an existing Thally project without replacing its runtime. See [MCP Server](/guides/mcp-server) for setup instructions.

## After migration

Once the migration completes, start the dev server to review the output:

```bash
cd my-docs
npm run dev
```

Then run `create-thally-docs check` to catch any issues before publishing:

```bash
npx create-thally-docs check my-docs
```

Common post-migration tasks:
- Update `src/data/site.ts` with your logo and brand colors
- Replace placeholder images in `src/content/`
- Review the nav order in `docs.json`
- Set `THALLY_SITE_URL` before deploying

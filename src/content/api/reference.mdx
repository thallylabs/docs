Thally uses the `api` block on a `docs.json` tab to load one OpenAPI
specification. It then builds the API sidebar and endpoint routes from the
operations in that file.

## What Thally reads

For each operation, Thally reads:

- the HTTP method, path, summary, description, and tags;
- path, query, header, and cookie parameters;
- request bodies, responses, schemas, and local `$ref` values;
- server URLs and supported security schemes;
- examples that can prefill a request or response.

Webhooks are supported separately and use the `Webhooks` group unless you set
`webhookGroup`.

## How navigation is built

Operations use their first matching tag as the sidebar group. `tagsOrder`
controls which configured tags appear first. Untagged operations fall back to
`defaultGroup`, or `Endpoints` when you do not set one.

Generated routes include the specification ID, normalized path segments, and
HTTP method. For example, `GET /posts` in the default specification becomes:

```text
/api/default/posts/get
```

Set `navigation: false` when you want authored MDX pages to provide the API
navigation instead.

## Customize one operation

Use the exact `METHOD /path` key from your specification:

```json
{
  "tab": "API Reference",
  "api": {
    "source": "openapi.yaml",
    "overrides": {
      "GET /users/{id}": {
        "title": "Get a user",
        "description": "Retrieve one user by ID.",
        "badge": "Stable",
        "group": "Users",
        "slug": ["users", "get-user"]
      }
    }
  }
}
```

An override can set `title`, `description`, `badge`, `group`, `slug`, or
`hidden`. It changes Thally's presentation without changing your OpenAPI file.

## How Try It sends requests

The **Try It** panel starts with the first available server URL. It prefills
supported parameter examples, generates a cURL command, and sends requests
through the documentation site's `/api/try-it` route.

Thally can prefill HTTP bearer, HTTP basic, and header API-key schemes. Keep
real secrets out of `docs.json`; readers can enter their own credentials before
they send a request.

## Add context with authored pages

Use an authored MDX page when an operation needs a tutorial, workflow, or
explanation that does not belong in the OpenAPI description. Add an `openapi`
frontmatter value to pair the page with the generated operation:

```yaml
---
title: Retrieve a user
description: Look up one user and handle a missing record.
openapi: GET /users/{id}
---
```
